The headline number is only the start. Each card shows how much of the money is locked, how much vests later, and what the cap does year by year.

Guaranteed
Money the team owes even if the player is cut. Some is guaranteed at signing. Some only vests later, if he is still on the roster.
Cap hit
What a player counts against the salary cap in one season. It is not the same as what he is paid that year.
Dead money
Cap space still used by a player the team no longer has, mostly the part of a signing bonus not yet counted.

    Site setup

    For whoever runs the site. Contract numbers live in Airtable, the page and its rules live in code, and Vercel puts it online. This preview shows built-in data. On Vercel the same page reads Airtable every few minutes and falls back to the built-in data if Airtable is unreachable.

    1. Airtable holds the numbers

      Make a base with a table named Contracts and import data/contracts.csv from the project folder. Importing is easiest in a browser at airtable.com. After that the Airtable app is fine for edits.

      Create a personal access token with the data.records:read scope for that base. Copy the base ID from the base's API page.

    2. Working Copy keeps the code

      Create a repository, import the project files, commit, and push to a new GitHub repository. Every later change is a commit and a push from Working Copy.

    3. Vercel publishes it

      Import the GitHub repository as a project and add three environment variables: AIRTABLE_TOKEN, AIRTABLE_BASE_ID and, if your table is not named Contracts, AIRTABLE_TABLE. Deploy. The Vercel app then shows each deploy as it finishes.

    4. Koder edits the page

      Working Copy shares its repositories in the Files app, so Koder can open index.html from there. Change wording, add a glossary term, then commit and push in Working Copy. Vercel redeploys on its own.
