# PlainStats

Simple, analytical NFL contracts and stats site for everyday fans. Live at plainstatsnfl.com (Cloudflare Workers, deployed from this repo's main branch by GitHub Actions; see Shipping). Static single page plus API functions; data is JSON in `data/`. See README.md for the full data pipeline.

## Editing the page
- Edit `src.html`, never `index.html`. `build.sh` wraps `src.html` into `index.html`; a hook runs it after every `src.html` edit and blocks direct `index.html` edits.
- CSS has two layers in `src.html`: the original base styles, then the storefront redesign layer (apple.com / CraftedNBA-inspired: translucent nav, sentence-case labels, soft grey field, white panels). Put new styles in the redesign layer and follow its tokens (`--bg`, `--surface`, `--fg`, `--muted`, `--brand`, `--r`, `--r-lg`).
- No all-caps tracked labels, no hover lift on cards. Respect `prefers-reduced-motion` and keep dark mode working (both `prefers-color-scheme` and `[data-theme]`).
- Every table needs a filter search. The Roster Builder shows no contract costs.
- Must work on phones: the owner edits from Koder / Working Copy on iPhone.

- Every page has a clean URL (README "Views"). A new section needs an entry in `ROUTES` in src.html, `rewrites` in vercel.json (destination `"/"`, never `"/index.html"`: with `cleanUrls` that 404s on reload) and `APP_URLS` in `tools/build_seo.py`. Never give an app page a path under `/players`, `/teams`, `/draft` or `/weekly` (static pages). App pages may use `/learn/...`, but not the five explainer paths `build_seo.py` writes (`/learn`, `/learn/epa`, `/learn/success-rate`, `/learn/cap-hit`, `/learn/dead-money`, `/learn/guaranteed-money`): a static file always wins over a rewrite. Link with `href="/path"` or `pathOf(key)`, never `#key`. Give a new page a `PDESC` line too: the raw HTML of every app path gets its title, description, canonical and card from `pageMeta()` in `api/_page-meta.js` (on Cloudflare `cf/worker.js` for everyone; on Vercel `api/page.js`, the first, bot-only rewrite in vercel.json; keep it first). The Worker's path list (`run_worker_first` in `wrangler.jsonc`) and `cf/_meta.json` are generated from `vercel.json` and `index.html` by `tools/build_cf.py`, so a new rewrite there is all a new page needs.

## Data rules
- Never copy Over The Cap, Spotrac or other restricted sources. Contract figures come from `data/ledger.csv` (named report + URL), CBA calculations (`data/cba.json`, `data/rookie_scale.py`) or stay unverified.
- A contract figure without a named report shows "Contract being verified". Do not guess numbers.
- No Pro Football Reference or Next Gen Stats data, with one written exception: nflverse `snap_counts` (PFR's copy of the official gamebook snap counts; no free in-season alternative). Never use nflverse `pfr_advstats`; pass rush comes from box-score sacks and QB hits.
- Free data only, current season (2026). Pipeline: `data/build_contracts.py` → `data/fix_ol.py` → `data/build_market.py`. Run Python with `python3 -I`.
- The nflverse rebuilds run in GitHub Actions (`.github/workflows/nflverse-refresh.yml` → `tools/refresh.sh daily|gameday|weekly`). A new nflverse build step goes in `tools/refresh.sh`, not only in a scheduled-task prompt.
- A hook checks that any edited `data/*.json` still parses.
- `data/build_contracts.py` takes a player off his team when the nflverse roster no longer lists him there (newest row cut or retired, or the team has posted a newer week without him; reserve lists are left alone). The row is parked in `data/off_roster.json` (build input, kept out of the deployment) and comes back if the roster lists him on that team again. A ledger deal signed after that roster week keeps him.
- Contract end years (`end` in `data/ledger.csv`): it is the LAST season under contract (the page shows free agency as end + 1). An extension adds its years onto the old contract, so end = old contract's final season + years added; it never starts in the current season unless the old deal already expired. Rookie deal ends are draft year + 3 (+ 4 with an exercised fifth-year option). Prefer a report's "through 20XX" over arithmetic; when two named reports disagree, leave `end` blank rather than pick one, and say in notes when it is calculated. Write the derivation in `notes` ("old deal through 2026 plus 2 years"). A re-signing of an expired deal is a Signing, not an Extension. Cards in the Airtable Contracts table and `DEALS` must show the same end year as the ledger.
- Recent deals stay current: every news sweep that adds a signing, extension or restructure to `data/ledger.csv` / `data/moves.json` must also add a breakdown card to the Airtable Contracts table (base `app7vEpDdwBT0xCUr`, table `tblMvDcAIUpr9Zuor`) in the same format as the existing cards (Name, Team, League, Position, Headline, Subhead, NewMoneyPerYear, Scale, ScaleNote, Bar, Facts, Plain, Watch, Sources, CheckNotes, Sort 0, Verified), and mirror it at the top of `DEALS` in src.html. Use only figures the named report gives; say what was not reported instead of guessing. Newsome and Adebawore (Nov 3, 2026) are the model for thin-report cards.
- Featured deal breakdowns live in Airtable (Cap Tracker base). `/api/contracts` only serves a deal with `Verified` ticked and at least one `Sources` line (`Outlet | https://link`). Tick Verified only after every figure on the card is checked against those reports; record what was checked or calculated in `CheckNotes`. The built-in `DEALS` in src.html is the fallback and must match the verified Airtable records.

- News items in `data/moves.json` carry `gids` (one gsis id per name in `players`, `""` for coaches). Every news sweep writes them; `python3 -I tools/refresh_helpers.py news-gids` fills what it can and lists the rest to fill by hand (the news name can differ from the roster: "Riq" / "Tariq Woolen"). Player pages show their "In the news" lines by gid only.

- Trade deadline page (`/trade-deadline`) is built from `Trade` items in `data/moves.json`. Every news sweep that adds a trade must also give it a `deal` field (README, "trade deadline page"): for each team, the players it gets (name, gsis id, team that sent him) and the picks it gets, as the report states them; add `dead` only when a named report gives the old team's dead money. Never guess a pick's year or round; leave it out and say so in `plain`.

## Search pages (SEO)
- `players/`, `teams/`, `draft/`, `learn/`, `weekly/`, `sitemap.xml` and `tools/seo-nav.html` are generated by `python3 -I tools/build_seo.py`. Never edit them by hand; edit the script. Re-run it after every `data/*.json` change (including the daily refresh), then run `./build.sh` and commit the generated files.
- Player titles and descriptions lead with the page's search intent (contract, rookie contract, salary or stats: `page_intent()` in `build_seo.py`, README). A contract a named report confirms always leads, and pay-led pages open with the searched pay questions as headings (`pay_questions()`). Sitemap `lastmod` and JSON-LD `dateModified` are per page, from `data/lastmod.json` (generated; never edit by hand, commit it with the pages).
- URLs: `/players/<name>`, `/teams/<team>`, `/teams/<team>/cap`, `/teams/<team>/dead-money`, `/draft/<name>`, `/learn/<term>`, plus hubs `/teams`, `/players`, `/draft`, `/learn`, and the weekly pages `/weekly`, `/weekly/<usage-risers|team-tiers|power-rankings>-week-<n>` (from `data/weekly/`, written by `python3 -I tools/refresh_helpers.py weekly` from the built page: never compute power rankings or usage lists a second way in Python; README "Static weekly pages"). Static HTML, inline CSS, no JavaScript apart from one inline snippet in `build_seo.py`: `GA` (Google Analytics 4 plus the cookie notice; loads only after Accept, shares the `pc.consent` choice with the app, live domain only). Keep the measurement ID in `GA` equal to `ANALYTICS.ga4` in `src.html`.
- The script follows the data rules: contract figures appear only when the player's `ver` letters confirm them; players with no confirmed contract get "Contract being verified" and `noindex` (kept out of the sitemap until a named report confirms the deal).
- Google is shown a player page only when it says something other sites do not: he has a PlainScore, or a named report confirms his contract (`thin` in `build_player()`). Rookie-scale, minimum-salary and unverified pages without a PlainScore are still built and linked, but carry `noindex` and stay out of the sitemap. Do not widen this without a reason: Google marked the whole site down on Nov 8, 2026 after turning down hundreds of near-identical pages. One exception (owner, Nov 23, 2026): a page Google showed 20+ times in one week stays indexable if a contract figure is confirmed (named report or CBA); the slugs are in `data/search_seen.json` (build input, hand-edited by the Monday Search Console task, never trimmed).
- Player pages carry a game log (`gamelog_html()`: one row per game from `history.json`, with target, carry and snap shares from `data/usage.json`). Team pages carry the weekly tier and EPA ranks (`team_form()`), schedule and results (`team_schedule()`), this week's injury report (`team_injuries_html()`) and the full roster with PlainScores (`team_roster_html()`; yearly pay only when `contract_facts()` confirms it). Keep these when reworking the pages: they are what makes a page more than a template. Each page repeats its FAQ in visible text and in JSON-LD; do not add schema for text that is not on the page.
- Player and team pages end with doorway links into the app (`player_doors` / `team_doors` in `build_seo.py`; the app's player sheet and team page carry the same block from `playerDoors` / `teamDoors` in `src.html`, so change both together) and The Cap Sheet signup (`signup_html`). The signup is a plain no-JS form that opens the beehiiv hosted subscribe page (`CAP_SHEET_URL`); left empty, it links to `/?signup=1`, which scrolls to the home-page signup.
- Team cap space and dead money pages use the team totals in `data/nfl.json` and say so; update their wording if those totals are re-sourced.
- Player comparison pages (`/players/<a>-vs-<b>`, `build_vs_pages()` in `build_seo.py`): pairs come from rules (teammates splitting the work, top confirmed deals, same draft class QBs) plus `data/compare_pairs.json` (hand-edited, from the Monday Search Console "Player vs. player searches" table). `data/vs_pairs.json` is generated; never hand-edit. Same data rules as player pages: pay only when `contract_facts()` confirms it, and say where it comes from (named report or CBA calculation).
- Social cards: `build_seo.py` also writes `og-data/*.json` (generated, never hand-edited) and every page's `og:image` is `/api/og?k=&s=&v=`, drawn by the function `api/og.js` using `api/_og-layout.js` and `assets/fonts/`. Card text is built in `build_seo.py` under the same data rules as the page. Keep `Allow: /api/og` in `robots.txt`. Preview layout changes with `tools/preview_og.mjs` + `tools/shot_og.py`; the sandbox can't reach ESPN or npm, so confirm the live `/api/og` URL after deploy.
- "Share this" (last `<script>` in `src.html`) puts a button on every panel with a chart or table; styles are in the redesign layer (`.ps-*`). Keep the offscreen copy out of the observer (`.ps-cap`) and read typed filter values from the live panel, not the clone.

- Share card (last `<script>` in `src.html`): a "Share" button on every player sheet, prospect sheet and team page (`data-card="p-…" | "d-…" | "team-XX"`, added by `sheetLink()` and `renderTeam()`) draws a 1080x1350 PNG on a canvas and opens the "Share this" preview (`window.psShowImage`). `playerSpec` (from `plainScore()`) / `teamSpec` / `prospectSpec` pick 3 to 5 percentile bars from numbers the page already computed; a card with fewer than three bars is not made. The data rules apply: a player whose contract is "being verified" gets no pay bars. The static pages in `build_seo.py` have a plain "Share" link to the app with `?share=1`, which opens the card as soon as the data loads. `tools/check_pages.py` checks each card is 1080x1350.

- PlainScore (0 to 100): a player's play-rating rank among qualified players in his rating group, as a percentile, with the bars behind it (top-weighted rating stats, plus yearly pay only when his contract is confirmed). `plainScore(p)` in `src.html` is the one definition: it feeds the panel at the top of the player sheet (`plainScoreHTML`), the player share card and `window.__plainScores()`. `python3 -I tools/refresh_helpers.py plainscore` (run `./build.sh` first) writes that to `data/plainscore.json` (build input, kept out of the deployment), and `build_seo.py` prints it on `/players/<name>` with a matching FAQ answer. Never compute PlainScore a second way in Python. Re-export before `build_seo.py` whenever `data/stats.json` or contracts change; `tools/refresh.sh` does it on every run. The glossary entry is in `LEARN_NFL` (Cap 101).

- Stat explainers: `/learn/epa`, `/learn/success-rate`, `/learn/cap-hit`, `/learn/dead-money`, `/learn/guaranteed-money` (`LEARN` / `learn_content()` in `build_seo.py`). Each gives a short answer, how it works, a worked example with round made-up numbers labelled "Example", and this season's numbers under the data rules (team totals say so; contract figures only when `ver` confirms them). Column headers link to them with a small ?: `linkHeads()` / `EXPLAIN` in `src.html` for app tables (first matching column per table, by header text then its title), `th_x()` in `build_seo.py` for static tables. Add a new term in both places.

- Share links: Copy link, Share this and Send to a friend build their address with `shareUrl()` in `src.html` (utm_ tags, and `/players/<name>` or `/draft/<name>` when the page exists). `build_seo.py` writes `data/pageslugs.json` for that lookup; do not edit it by hand.

- Match players across data files by gsis id (`gid`, row index 19 in `data/nfl.json`), never by name: nflverse files spell names differently (Greg / Gregory Rousseau). `data/stats.json` rows carry `gid`.

- Season stats load from small files in `data/hist/` (built by `data/build_hist_split.py`, run by `build_history.py` and `build_history_old.py`): `meta.json`, `s<year>.json`, and 64 player shards `p<NN>.json` keyed by gsis id. The page never loads `history.json` / `history_old.json` (build inputs, kept out of the deployment). Match players by `gid`, never by team, so mid-season trades stay one record.

- Games tab (`/scores`, `/standings`, `/projections`, game pages `/game/<id>`): `data/schedule.json` (daily, `data/build_schedule.py`) and `data/projections.json` (weekly, `data/build_projections.py`, PlainStats Elo model). Never use the betting columns in nflverse games.csv. This week's game pages use `data/gameday.json` (daily, `data/build_gameday.py`: official injury report via nflverse plus injury-adjusted picks) and live weather from api.weather.gov (public domain, fetched in the browser; the sandbox can't reach it).

- Analytics: GA4 events go through `psTrack()` in src.html (static pages: the `GA` snippet in build_seo.py). Every new feature gets an event, listed in README "Analytics events". Search Console is read weekly by `.github/workflows/search-console-weekly.yml` (`tools/gsc_report.py`).

## Checks
- `python3 -I tools/check_pages.py` opens every view at phone and desktop size, light and dark, and fails on JS errors, failed data loads or sideways scroll. Run it before pushing page changes (`--shots DIR` saves screenshots).
- `python3 -I tools/check_stats.py <nflverse folder>` checks every player card's season stats (On the field tab) against the raw nflverse box scores, by gsis id, and flags players listed twice. Run it after rebuilding `data/stats.json`. Missing cards, duplicates, fewer games than box scores, or more than max(5, 1%) stat mismatches block the stats step; a few mismatches print `WARN`, publish anyway and open the "nflverse refresh needs attention" issue (closed by the next clean run). `--strict` fails on any mismatch.
- `python3 -I tools/check_ledger.py` checks `data/ledger.csv` for missing sources, totals that don't add up and duplicates. After adding ledger rows, have the `ledger-checker` agent compare them with their source links.
- `python3 -I tools/check_a11y.py` runs axe-core (fetched once from npm into `~/.cache/plainstats/`) on the same views as `check_pages.py`, phone and desktop, light and dark, and lists failing rules (`--impact`, `--views`, `--url`, `--json`). Report only for now; it is not in CI.
- `python3 -I tools/nfl_transactions.py [--since DATE]` reads the NFL.com transaction wire and lists trades and releases missing from `data/moves.json`, released players still on a roster in `data/nfl.json`, and new signings not on one yet. The wire is an official named source for the fact of a move, never for contract figures. Names are matched loosely (the wire has no gsis id): treat a match as a lead, never as a gid.
- Data cross-check (`.github/workflows/data-crosscheck.yml`, daily 9:05 AM PT): `tools/check_espn.py` compares our nflverse injury report and depth charts with ESPN's public API (matched by gsis id through nflverse `players.csv`), plus the transaction wire. Report only, in the one issue "Data cross-check" (label `crosscheck`), body replaced each run. ESPN data is never shown on the site. The sandbox can't reach ESPN; the workflow can.
- PageSpeed (`.github/workflows/pagespeed-weekly.yml`, Wednesdays): `tools/psi_report.py` runs Lighthouse through the PageSpeed Insights API on the main landing pages and posts an issue labelled `pagespeed`, with the change from last week. Needs the repo secret `PSI_API_KEY` (a free Google Cloud key); without it Google answers 429.
- Agents in `.claude/agents/` (each reports back; the main session builds, checks and commits):
  - `news-sweep`: the news sweep in one pass (`moves.json` with gids and trade `deal`, ledger rows, Airtable card, `DEALS` mirror). Follow it with `ledger-checker` on the new rows.
  - `ledger-checker`: compares new ledger rows with their source links.
  - `stats-checker`: explains `check_stats.py` FAIL/WARN lines (build bug, duplicate, missing card, stat correction or by design). Use when the "nflverse refresh needs attention" issue opens.
  - `search-console-analyst`: turns the Monday `search-console` issue into a ranked to-do list for the static pages and adds searched pairs to `data/compare_pairs.json`.
  - `seo-page-reviewer`: checks the generated search pages (thin or near-duplicate pages, sitemap vs noindex, titles, FAQ vs JSON-LD, data rules, links) after `build_seo.py`, before committing.
  - `accessibility-checker`: runs `check_a11y.py` plus keyboard, reduced-motion and zoom checks, and gives fixes that follow the redesign-layer tokens. Findings checked by hand and found fine go in `KNOWN_OK` in `check_a11y.py`, with the reason and date.
- Scheduled tasks run the agents (set up Nov 18, 2026): the daily refresh (6:36 AM PT) hands its news items to `news-sweep`, then `ledger-checker`; the Monday Search Console task (10 AM PT) runs `search-console-analyst` and commits new comparison pages; "PlainStats daily checks" (9:38 AM PT, after the 8:10 AM workflow) runs `stats-checker` (only when the attention issue is open), `seo-page-reviewer` and, on Wednesdays or after a page change, `accessibility-checker`; "PlainStats weekly refresh" (Tuesday 8:36 AM PT, after the 7:10 AM weekly workflow run, which it reruns with `tools/refresh.sh weekly` if it failed) updates the Draft page boards and college stats (`data/build_draft.py`), runs the full headless checks, republishes the artifact and sends the weekly message; "PlainStats monthly refresh" (the 1st, 11:17 AM PT) updates official figures in `data/cba.json` (cap, minimum salaries, tenders, practice squad pay, tags, rookie scale signings, fifth-year options) and the calendar and tags in `data/freeagency.json`, runs a full contract audit with `ledger-checker` on every changed row, rebuilds contracts and the search pages and runs the checks (it never rebuilds stats history). The owner approved small safe fixes being pushed to main by that task (a color or heading tag, an aria label, a broken link, a short builder fix). The `thin` rule, indexing, figures and anything bigger go to the issues "Search pages need attention" / "Accessibility needs attention" (stats: "nflverse refresh needs attention"). Change what a task does in its prompt, and keep this list in step.
- `.mcp.json` adds Playwright (browser checks), Airtable and Google Search Console for Claude Code sessions (the Vercel server was removed Nov 20, 2026: deploy logs are in the GitHub Actions "Cloudflare deploy" runs).
  - Airtable (`https://mcp.airtable.com/mcp`, the official server): signs in with OAuth on first use (`/mcp` in Claude Code). Cloud sessions that already have the claude.ai Airtable connector (`mcp__Airtable__*`) can use that instead. The Contracts table rules above apply either way.
  - Search Console (`mcp-server-gsc`, a community server, pinned to 0.3.0; read-only `search_analytics`): needs `GSC_CREDENTIALS_FILE` set to the path of the same service account JSON key the weekly workflow uses (the `GSC_SERVICE_ACCOUNT` secret; Restricted access is enough). Never commit the key. Without the variable the server does not start; cloud sessions keep using the Monday `search-console` issue. Check the package before raising the pinned version.

## Shipping
- The site is served by Cloudflare Workers (Vercel Hobby paused Nov 20, 2026 for Fast Origin Transfer; nothing points at Vercel now). `.github/workflows/cloudflare-deploy.yml` deploys on every push to main and after each nflverse refresh run: `tools/build_cf.py` copies only public files into `dist/` (`.vercelignore` is the exclude list for both hosts) and writes `_redirects` / `_headers` from `vercel.json`, so keep editing `vercel.json`; `tools/render_og.mjs` draws every social card into `dist/og/<kind>/<slug>.png` (the free plan's CPU limit can't draw them per request; unchanged cards come from actions/cache); then `wrangler deploy` (`wrangler.jsonc`, domains included). `cf/worker.js` runs only for `/api/*` and app paths: `/api/og` serves the drawn card, `/api/contracts` reads Airtable (Worker secret `AIRTABLE_TOKEN`) with the same filter as `api/contracts.js`, and app paths get `index.html` with their own head (HTMLRewriter, `pageMeta()`; unknown app-shaped paths are a 404 for bots). `/api/espn-csv` is not ported; the page falls back. `vercel.json` has `git.deploymentEnabled: false`, so the paused Vercel project never builds from pushes again (the Vercel Web Analytics snippet was removed the same day). On Vercel, function output is what Fast Origin Transfer meters: keep the bot rewrite limited to app paths and named search/preview bots, and keep function caches long.
- Push changes to GitHub without asking first (standing instruction from the owner).
- Secrets (`AIRTABLE_TOKEN`) live only in the Cloudflare Worker secrets (and Vercel env vars); `CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` are GitHub Actions secrets. Never commit them.

## Keeping the setup private
- `.vercelignore` keeps notes, build scripts, `src.html`, `tools/` and raw sources (`data/*.py`, `*.csv`, `*.txt`, `cba.json`, `years_calc.json`) out of the public deployment. If the page starts loading a new `data/` file, make sure it is not matched there. Keep the GitHub repo private.
