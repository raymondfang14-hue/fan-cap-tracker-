# PlainStats

Every NFL contract and team salary cap in plain English, for everyday fans.

## Files
- `src.html` is the page (also published as the PlainStats artifact). Edit this one.
- `build.sh` wraps `src.html` into `index.html`, which Vercel serves. On a phone, edit `index.html` directly in Koder and make the same change in `src.html`.
- `data/nfl.json` holds all 32 teams' cap figures and every player contract. `data/moves.json` is the NFL news feed (contract moves, injuries, games, coaching, league news) and the trade deadline date. A daily scheduled task refreshes both. Every news item carries `gids`, one gsis id per name in `players` (`""` for coaches and people with no gsis id); `python3 -I tools/refresh_helpers.py news-gids` fills any that are missing (from the trade's `deal`, else the one roster or stats row with exactly that name) and prints the names it could not place, and `tools/refresh.sh` runs it every time.
- Player pages (the app's player sheet, `fillLatest()` in src.html, and `/players/<name>`, `latest_html()` in tools/build_seo.py) open with a "Latest" box: up to two news items from the last 30 days that name him by gid, his line on the latest week's official injury report (data/injuries.json, only when he is on that week's report) and his last game (week, date, result and box-score line from the season game log and data/schedule.json; "Last played" when his team has played since). Change both together.
- `data/season.json` holds standings (record, points for and against), head coaches, 2025 records, the rookie and comeback-candidate lists, and `prevRanks` (last week's power ranking, for the movement arrows). It feeds the Awards and Power rankings page (`#awards`, `#rankings`), which scores everything in the browser from `data/stats.json` plus this file, so a data refresh updates the page.
- `api/contracts.js` reads the featured deal breakdowns from Airtable (optional).
- `data/contracts.csv` is the starting data for the Airtable `Contracts` table.

## Vercel settings
Add `AIRTABLE_TOKEN` (a personal access token with `data.records:read` on the Cap Tracker base). The function already points at the Cap Tracker base and its deals table; set `AIRTABLE_BASE_ID` or `AIRTABLE_TABLE` only to use a different one. Without them the page shows its built-in breakdowns.

On plainstatsnfl.com (and localhost or vercel.app) they are real paths; `vercel.json` rewrites them to index.html and the page routes on `location.pathname` (`ROUTES`, `pathOf()`, `keyOfPath()`, `go()` in src.html). In the artifact preview the same keys use the `#hash` instead. Old `/#key` links are moved to their path on load.

Inside each section tab, every panel is its own page with a row of page links under the tab (`SUBS` in src.html: box, page, label, route key, path; panels carry `data-sp`). The tab's address opens its first page; the rest live under it, e.g. `/contracts/all-players`, `/free-agency/by-team`, `/big-board/full`, `/projections/playoff-odds`, `/cap-lab/spending-heatmap`. Team pages work the same way: `/team/<code>/<lineup|stats|depth-chart|cap|spending|playing-well|news|roster>` (`TEAMSUBS`). Adding a sub-page: add it to `SUBS`, tag its panel with `data-sp`, and add the path to vercel.json `rewrites` and the sub-page list in tools/build_seo.py.

A player card opens at `/players/<name>` when the player has a static search page, else `/player/<first-last>-<team>`; a prospect at `/draft/<name>`, else `/prospect/<id>`. Typing those static URLs directly gives the static page, which links into the app. `/players`, `/teams` and `/draft` stay the static hubs, so no app path may use them. App paths may sit under `/learn`, apart from the stat explainer pages `build_seo.py` writes there. Crawlers and link-preview bots (any User-Agent with bot, crawler, spider, facebookexternalhit, WhatsApp and a few others) get app paths from `api/page.js` instead, through the first rewrite in vercel.json: the same index.html with that page's own title, description (`PDESC`), canonical and social card, and a real 404 for paths that are not pages. Static files always win over rewrites on Vercel, so `/players/...`, `/data/...` and `/api/og` are never affected. `api/page.js` reads the `ROUTES` ... `TEAMSUBS` block of index.html, so keep that block plain data. When adding a page: add it to `ROUTES` (and `PTITLE`, `PDESC`, `SPAGES` for search) in src.html, to `rewrites` in vercel.json and to `APP_URLS` in tools/build_seo.py (sitemap). index.html has `<base href="/">` (build.sh) so relative data/ URLs work on deep paths.

The trade deadline page (`/trade-deadline`, `renderTD()` in src.html) lists every `Trade` in data/moves.json dated on or after Week 1 (first game in data/schedule.json). Each trade may carry `"deal": {"<TEAM that gets them>": {"players": [{"name", "gid", "from"}], "picks": ["2027 1st-round pick"], "dead": <dollars, only when a named report states it>}}`. Without `deal` the page falls back to `teams[0]` = sender, `teams[1]` = receiver and matches `players` by name on the receiving team. The salary that moves is calculated as base salary × weekly paychecks left ÷ 18, only for players whose 2026 salary is CBA-calculated or confirmed (`ver` has c and b); everyone else shows "Contract being verified". "Open in trade checker" links to `/trade-checker?a=&b=&pa=<gsis ids>&pb=&d=<iso>`, which replays the deal with each player on the team that sent him.

**Social links (/ig, /tt, /links, carousel end slide).** Social traffic is measured three ways, because Instagram and TikTok captions cannot link and a bio link to the home page shows up as direct traffic:
- *Bio links.* Put `plainstatsnfl.com/ig` in the Instagram bio and `plainstatsnfl.com/tt` in the TikTok bio. `vercel.json` redirects them (307) to `/links/instagram` and `/links/tiktok` with `utm_source=instagram|tiktok&utm_medium=social&utm_campaign=bio`. GA4 credits the platform (Reports > Acquisition > Traffic acquisition, session source), for visitors who accept cookies. Vercel Web Analytics has no UTM breakdown on this plan, so each platform lands on its own path: the Pages list in Vercel shows `/links/instagram` and `/links/tiktok` for every visitor, no cookies needed. Both paths are one page (canonical `/links`).
- *Any page, tagged.* `/ig/<path>` and `/tt/<path>` redirect to `/<path>` with the same tags and `utm_campaign=post`, for Story link stickers, comments and DMs (e.g. `plainstatsnfl.com/ig/team-tiers`).
- *The /links page* (`renderLinks()` in src.html) lists recent posts from `data/links.json`, newest first, then fixed "Start here" links (`LK_START`). Add one entry per post at the top of `posts`: `{"date": "2026-11-11", "title": "Team tiers, Week 10", "path": "/team-tiers", "platform": "both"}` (`platform`: `instagram`, `tiktok` or `both`; `/links/instagram` hides TikTok-only posts and the other way round). Use the exact path printed on the post's end slide. A tap is the GA4 event `links_click`.
- *Carousel end slide.* Every "Share this" and "Share" card preview has **Make end slide**: a 1080x1350 slide reading "See the full table" (or "See the full page" for a player, prospect or team card), the page's title and its exact address (`pathOf(curKey())`, e.g. `plainstatsnfl.com/team-tiers/offense-vs-defense`), and "Tap the link in our bio". Save it as the last slide of every carousel. Drawn by `endDraw()` / `window.psEndSlide` in the share-card script; `tools/check_pages.py` checks it is 1080x1350.

The home page opens with "Your team" (`renderMine()` in src.html) under the search: the favorite team (localStorage `pc.fav`, set there or with "Make this my team" on a team page) with its next game and the model pick (`gPick`, injuries and weather included this week), this week's injury report for that game (data/gameday.json), its three latest news items, and cap room and dead money (data/nfl.json). With no favorite it is a one-line team picker. The games files load in the background and the block redraws when they arrive.

The home search (`searchEverything()` in src.html) searches pages, teams, players, prospects, this and last week's games, news headlines and Cap 101 terms.

## Automatic nflverse refresh (GitHub Actions)
`.github/workflows/nflverse-refresh.yml` runs `tools/refresh.sh` on a schedule and pushes to main: **daily** (8:10 AM PT: contracts rebuild from roster, draft picks, snap counts and depth charts, older seasons, scores, this week's injury report), **gameday** (Thursday, Sunday and Monday nights: scores, stats through the week being played, standings, game model) and **weekly** (Tuesday 7:10 AM PT: stats through the last finished week, splits, history, standings, game model, OL measures, team tiers). Each run rebuilds the search pages and index.html and runs the checks; a data step that fails is restored from git and the rest is pushed, and nothing is pushed if the page check or the script parse fails. Run it by hand from the Actions tab (Run workflow, pick a mode) or locally with `tools/refresh.sh <mode> [folder]` (`SKIP_PAGE_CHECK=1` skips the five-minute page check). The Claude scheduled tasks keep the work that needs judgment: news, the contract ledger, contract verification, the draft boards, cba.json and the free agency calendar. If Vercel ever skips deploying the workflow's commits, add a Vercel deploy hook as the repository secret `VERCEL_DEPLOY_HOOK`.

## Search pages (players/, teams/, draft/, sitemap.xml)
`python3 -I tools/build_seo.py` turns the data files into crawlable pages: one for every player with a confirmed contract or 2026 stats, three per team (overview, cap space, dead money), one per draft prospect, and hub pages for teams, players and the draft. Each has its own title, description, plain-English summary, FAQ and schema markup (Person, SportsTeam, FAQPage, BreadcrumbList), and the script rewrites `sitemap.xml` and `tools/seo-nav.html` (the team links `build.sh` adds to the bottom of the home page). Players whose contract is still being verified get `noindex` and stay out of the sitemap until a named report confirms the deal. Run it after every data refresh, then `./build.sh`, then commit.
Player page titles and descriptions follow search intent (`page_intent()` / `player_meta()`): a veteran with a reported deal leads with the contract ("X contract: $112.0M through 2029"), a player on a calculated rookie-scale deal with "X rookie contract", an undrafted player with "X salary", and a player who qualifies for a PlainScore and is not on a reported deal of $5M a year or more (`BIG_DEAL`) with "X 2026 stats and contract" (the season then sits above the contract on the page). Titles stay within 60 characters (`fit()`), descriptions within 158 in whole sentences (`pack()`), and contract figures still come only from `contract_facts()`.
Each sitemap URL has its own `lastmod`: `data/lastmod.json` (generated, build input, not deployed) keeps a hash of each page's title, description and main text and the date that text last changed, and the same date goes into the page's JSON-LD `dateModified`. A refresh or a script/style change that leaves a page's words alone keeps its date. The home page and app pages use the data date, since they show live numbers.
To submit to Google: add `https://www.plainstatsnfl.com` as a property in Search Console, open Sitemaps and submit `sitemap.xml`.

## Social cards (og-data/, api/og.js, api/_og-layout.js, assets/fonts/)
Every generated page has its own link-preview image (1200x630: player face or team logo on the team color, the name, one big number) so links look right on X, iMessage, Reddit and Discord. The pages point `og:image` at `/api/og?k=<players|teams|draft|pages>&s=<slug>&v=<data date>`. `tools/build_seo.py` writes the text for each card to `og-data/<kind>.json` (so a contract number appears only when the page would show it, and unverified players lead with a real 2026 stat and "Contract being verified"). `api/og.js` is a Vercel function (Node runtime, no `runtime: edge`: the edge build of @vercel/og fails to compile its wasm) that looks the slug up, fetches the headshot and logo from ESPN's image CDN (the build sandbox can't reach it; if an image is missing the card shows initials), draws the card with `@vercel/og` and Inter from `assets/fonts/`, and the CDN caches it for a day. Anything that goes wrong redirects to the static `og-image.png`. Only the slug comes from the URL, so nobody can make the domain draw a card with their own text. `robots.txt` must keep `Allow: /api/og`: X, Facebook and Reddit obey it for the image.
Check a card's layout without deploying: `node tools/preview_og.mjs OUT_DIR [IMAGE_DIR]` then `python3 -I tools/shot_og.py OUT_DIR`. The final check is the live `/api/og?...` URL, and a page you want X or Facebook to re-read after a change needs their card validator or a new `v=` value (the build bumps it every refresh).

## Share this (src.html, last script block)
Each panel that holds a chart or table gets a "Share this" button. It copies the panel offscreen (the live page never changes), drops the controls, keeps the filters as a small "Filter: ..." line, caps tables at 20 rows with a note, adds a small PlainStats watermark and the data date, and photographs the copy with `html-to-image` (loaded from jsDelivr on first click only). A preview opens with Share (phones), Save image and Copy image. ESPN logos and headshots are copied in only if ESPN's CDN allows it from the browser; otherwise they are left out of the image rather than breaking it. `tools/check_pages.py` fails if the buttons stop appearing.

**Weekly Search Console report.** `.github/workflows/search-console-weekly.yml` runs `tools/gsc_report.py` every Monday and posts a GitHub issue (label `search-console`, title "Search Console: weekly report, week of ...") on the last 7 days of data against the 7 before, for the whole site:
- **By section**: impressions, clicks and click rate for player pages, player comparisons, team pages, draft prospects, stat explainers, app pages and the home page.
- **Searches to win next**: searches at average positions 4 to 20 with 20+ impressions, each with its position change, the page Google showed most and that page's `<title>` in the current build (app pages say "app page"), ranked by clicks within reach: impressions x the site's own top-3 click rate that week, minus clicks so far. The estimate is left out (and the list ranked by impressions) when the top 3 had under 50 impressions. This is the list for title and description work: does the page answer the search?

## Where contract numbers come from (data/nfl.json, data/ledger.csv, data/cba.json)
PlainStats does not copy Over The Cap or Spotrac. `data/build_contracts.py` builds every player row and tags where it comes from:
- `r` reported: `data/ledger.csv` has one row per deal from a named news report or team announcement, with its URL. Blank fields stay unverified and the player page says so.
- `f` calculated: rookie contracts for the last four draft classes, from the draft slot with PlainStats' rookie scale (`data/rookie_scale.py`, anchored to real 2026 signings listed in `data/cba.json`) and the CBA minimum salaries, including the proven performance escalator, fifth-year options and trades. Undrafted rookies get the minimum.
- `m` league minimum and `p` practice squad: valued with the CBA tables in `data/cba.json`. Undrafted players from the last two classes are `m` rows with only this season's CBA minimum base salary (index 11, `ver` letter `s`); their length, signing bonus and guarantees stay blank, the app keeps them out of pay rankings (`hid`) and the pages say those terms are being verified.
- `u` unverified: no sourced figure yet. The dollar fields are blank in `nfl.json` and the page says "Contract being verified". The daily refresh moves these into the ledger (starting with quarterbacks and the best-known players, using nflverse snap counts to choose), and `data/build_market.py` waits to rebuild the price ladder until most contracts are verified.
- Suggest a fix: the button on every player sheet and in the footer opens a form that composes an email to info@plainstatsnfl.com. A contract figure changes only when the sender's link, or our own search, finds a named report.
Run `python3 -I data/build_contracts.py <folder with nflverse roster_2026.csv, draft_picks.csv, snap_counts_2023-2025.csv>`, then `data/fix_ol.py`, then `data/build_market.py`.
- `data/years_calc.json`: rookie-deal cap hits by season, still written by `build_contracts.py` but no longer shown anywhere. The site shows no season-by-season cap hits, since reports rarely publish them.
- `data/freeagency.json`: PlainStats cap projection (2026 cap grown 7% a year), the offseason calendar and official franchise tag prices once announced.
- Team cap space and dead money per team are still the older figures until enough contracts are re-sourced to add them up.
## Offensive line team measures (data/olwin.json)
Built by `python3 -I data/build_olwin.py <play_by_play_2026.csv.gz>` from nflverse play-by-play: pass protection (dropbacks with no sack or QB hit) and run success (designed runs with positive expected points). PlainStats no longer uses ESPN win rates or PFF figures.

## Weekly team tiers (#tiers, data/tiers.json)
`/team-tiers` plots every team's offense EPA per play against defense EPA allowed per play (team logos, top-right = good at both), groups the 32 teams into five tiers by net EPA per play, and lists the splits (pass, run, hit rate) in a filterable table. `python3 -I data/build_tiers.py <play_by_play_2026.csv.gz>` writes `data/tiers.json` from nflverse play-by-play (CC BY 4.0) through the last week in which every game in `data/schedule.json` is final, plus the rank change from the week before. The weekly refresh (Tuesday) runs it in step 4e, right after `build_olwin.py`.

## Player comparison pages (/players/<a>-vs-<b>)
Static "Player A vs Player B" pages for the searches fans make, built by `tools/build_seo.py` (`build_vs_pages()`): the two players' season stats side by side (better number in bold), shares of team targets, carries and snaps (data/usage.json), PlainScore percentiles bar by bar, pay only when `contract_facts()` confirms it (with where the figure comes from), and an FAQ (who is better this season, who has more yards, the better fantasy option, who gets paid more) repeated in JSON-LD. The slug is the two player slugs in alphabetical order. Which pairs get a page:
- **searched**: `data/compare_pairs.json` (hand-edited, `{"pairs": [{"a": gsis, "b": gsis, "q": "the search"}]}`). The Monday Search Console issue has a "Player vs. player searches" table with the line to paste for each "A vs B" search whose names match one player each.
- **teammates**: two quarterbacks with 60+ attempts each, or two running backs splitting the carries (the second has 30+ and at least 40% of the first's).
- **paid**: the six biggest confirmed deals at QB, RB and WR and four at TE, all pairs (a tie at the cutoff takes every tied deal, up to eight).
- **class**: first-round quarterbacks from the same draft class (data/drafted.json).

Both players need a `/players` page, 2+ games this season and the same position group. `data/vs_pairs.json` (generated, never hand-edit, not deployed) keeps every pair ever built so a page stays up after its rule stops picking it. Each player page links to its comparisons ("<name> compared"), the `/players` hub lists them all at the bottom, and each comparison links to `/compare?p=<gsis>,<gsis>`, which opens the app's Compare tool on that pair (`cmpFromQuery()` in src.html). The app's Compare tool links back to the static page when one exists (`cmpVsLink()`, from `data/pageslugs.json` key `v`). Social card: `og-data/pages.json`, slug `vs-<slug>`.

## Weekly usage risers (/usage-risers, data/usage.json)
For fantasy players: whose share of his team's targets, carries and snaps jumped (or dropped) this week. `python3 -I data/build_usage.py <folder> <season> [last week]` writes `data/usage.json` from nflverse `stats_player_week_<season>.csv`, `snap_counts_<season>.csv` and `players.csv` (CC BY 4.0): every RB, WR, TE and FB with a target or carry, one row per game (targets, carries, PPR points, offensive snaps), plus each team's targets, carries and offensive snaps per game (targets and carries summed over every player, quarterbacks included; team snaps = the most any one player took, the offensive line's count). Snap counts are the written nflverse `snap_counts` exception and are matched by id (`pfr_id` -> `gsis_id` in players.csv), never by name; without them the script still runs with no snap share. Snap counts can arrive a day after the box scores: the page then says the week's snap counts are not out yet. The script checks its target share against nflverse's own `target_share` column and stops if they disagree. `tools/refresh.sh` runs it in the gameday and weekly modes right after the season stats, so a Monday-night run has the week ready for a Tuesday post.

The page (`renderUsage()` in src.html) compares a week's share with the player's pooled share over his earlier games this season ("before"). Risers need 5+ targets, 8+ carries or half the offense's snaps that week; fallers need 5+ targets or 8+ carries a game, or 60%+ of the snaps, over 2+ earlier games, and must have played this week. Three pages: Risers (the weekly post: the biggest jump as a one-line takeaway, then the top 8 target, carry and snap share gainers), Fallers, and All players (filterable, sortable table). A week picker reaches back to Week 2; a week still being played is marked "so far" and names the teams yet to play. A game counts when the player recorded a stat or took an offensive snap. No route data (that would need charting data PlainStats does not use).

**Weekly post.** Tuesday after the weekly refresh: open `/usage-risers`, "Share this" on the Risers panel (and Fallers if it is a good week), "Make end slide", and add the post to `data/links.json` with path `/usage-risers`. Caption hook: the takeaway line at the top of the panel.

## Draft (#draft, data/draft.json)
The Draft page covers the 2027 class: a big board, a full page for each prospect (grade, role, trait badges, 2026 college stats, NFL players in the same role, rookie contract, team fits), the projected first-round order with a model mock, and the rookie pay scale. `data/draft.json` is built by `python3 -I data/build_draft.py` from the prospect list in that script (WalterFootball and NFL Draft Buzz board ranks, cfbstats ids) the season totals in `data/draft_stats.txt` and the ESPN athlete ids in `data/draft_espn.txt` (prospect headshots; school logos use the ESPN team id at the end of each SCHOOLS row, the same ESPN CDN images the NFL cards use); the script's docstring explains the format. The page computes everything else at load: the consensus order, grades, roles, traits, team needs from the 2026 roster, the draft order from `data/season.json` with traded picks applied, and rookie pay grown with the projected 2027 cap from `data/freeagency.json`.

## Season stats, links, value, rookie deals (#stats, #p-..., #value, #rookies)
- `data/stats.json` (the player card's On the field tab and Players > ratings): built weekly by `python3 -I data/build_stats.py <dir> <season> data/stats.json [last week]` from nflverse `stats_player_week`, `snap_counts` and `players.csv`. No Pro Football Reference charting (`pfr_advstats`: pressures, hurries, blitzes, missed and broken tackles, coverage, drops, bad throws, contact yards) is used; pass rush is sacks and QB hits from the box scores, and team pass defense (`teams.dpe` in stats.json) is the passing EPA per dropback of the quarterbacks each team faced. Coverage for defenders is estimated from play-by-play (fields `ct`, `cc`, `cy`, `ctd`, `ci`, `ce`; needs `play_by_play_<S>.csv.gz` in the folder): an interception goes to the intercepting player, a broken-up incompletion to the player credited with the pass defensed, a completion to the first defensive tackler. About 75% of passes are credited by name; each team's remaining (uncredited) incompletions are shared among its corners and safeties in proportion to their credited targets, which puts catch rate allowed within about 2 points of charted figures on average. Against Pro Football Reference's charting through Week 8 of 2026, corners with 10+ targets matched at r = 0.83 (targets), 0.60 (yards per target), 0.65 (catch rate) and 0.53 (passer-rating-allowed rank); safeties are rougher. Estimated passer rating allowed runs low (corners average 67 against 84 charted) because most touchdown catches have no tackler and go uncredited; the ratings only use the order within a position, so this does not skew them. The page labels these numbers as estimates and uses them in the corner and safety play ratings. Players are joined across files by id (players.csv links the PFR id in snap counts to the gsis id in box scores), never by name, and each row carries `gid`; the page attaches a row to a card by `gid` first and never gives one player another's line. Pass the last week when a week is still being played. `data/build_contracts.py` merges contract rows that share a gsis id (the old list and the roster can spell a name differently), keeping the roster's spelling.
- `data/history.json`: regular-season box scores for every player from 2023 to the current season, plus this season's game log, built by `python3 -I data/build_history.py <dir> <season>` from nflverse `stats_player_week_<S>.csv` files. `data/drafted.json` (the last six draft classes, from nflverse `draft_picks.csv`) is written by the same script. `data/history_old.json` holds season totals (no game logs) from 1999 up to the season before history.json starts, only for players on a current roster; `python3 -I data/build_history_old.py <dir>` builds it from nflverse `stats_player_reg_<S>.csv` and re-matches the roster, so new signings pick up earlier seasons, and the page loads it only when a player's Stats tab opens. Weekly game logs are kept for the current season only. The page does not load history.json or history_old.json (they are build inputs, kept out of the deployment by .vercelignore; tools/build_seo.py still reads history.json). Both build scripts end by running `python3 -I data/build_hist_split.py`, which writes the small files the page loads from `data/hist/`: `meta.json`, one `s<year>.json` per season (totals, for Players > Season stats) and 64 shards `p<NN>.json` (a player's every season plus this year's game log, about 18 KB each, for the Stats tab). Players are keyed by gsis id, so a player traded mid-season stays one record (season line `t` = team with most games, `tt` = all teams). The page matches contract players to stats by `gid` (row index 19 of data/nfl.json). The files load only when someone opens the Season stats tab or a player's Stats tab. Players > Season stats also has a week range, a minimum-snaps qualifier and a garbage-time toggle (current season only). They read `data/hist/wk<season>.json`, written by `build_hist_split.py` from `history.json` plus `data/splits.json`, which `python3 -I data/build_splits.py <nflverse dir> <season>` builds from nflverse `play_by_play_<S>.csv.gz`, `snap_counts_<S>.csv` and `players.csv`. Garbage time = offense win probability under 5% or over 95% (rbsdm's cut-off), split out of passing, rushing and receiving stats only. Run `build_splits.py` before `build_hist_split.py` after each weekly refresh; `splits.json` is kept out of the deployment.
- Links: every player and draft prospect has its own URL (see Views); the player and prospect pages have a Copy link button that copies the www.plainstatsnfl.com address.
- Contracts > Best & worst: market value is today's price for a player who ranks where he ranks on the field (data/market.json), minus his yearly pay.
- Contracts > Rookie deals: draft classes matched to contracts by name and team; fifth-year option prices are rough CBA estimates.

## Hosted "Suggest a fix" form
Every "Suggest a fix" link (the app footer, player sheets, and the footer of each generated page) can open a Tally or Google Form instead of an email. Set `const FIX_FORM = '...'` in `src.html` (one line, read by `tools/build_seo.py` too); `{page}`, `{about}` and `{kind}` in the address are filled in with the page address, the player or team and the fix type. Tally: add hidden fields named `page` and `about`. Google Forms: use the "Get pre-filled link" address with `{page}` as the value. Empty keeps the old email form. When it is set, update the "Suggest a fix" paragraph in `privacy.html` (it says the form only opens an email app), then rerun `python3 -I tools/build_seo.py` and `./build.sh`.

## Games tab: scores, standings and the game model
- `data/schedule.json`: every regular-season game with kickoff (Eastern) and final score, from nflverse `schedules/games.csv`. Built by `python3 -I data/build_schedule.py <games.csv> 2026`; the daily refresh runs it so scores stay current.
- `data/projections.json`: standings (records, division and conference records, streaks, seeds if the season ended today) and the PlainStats game model, built by `python3 -I data/build_projections.py <games.csv> 2026` in the weekly refresh. The model is an Elo rating from every game since 1999 (K 20, home field 40, 40% regression to the mean each offseason), win chance and projected score for every game (played games keep their pre-kickoff pick), and 10,000 simulated seasons with simplified NFL tiebreakers and playoffs. It never uses betting lines. Backtest: about 65% of winners picked, 2012 to 2025.
- `data/gameday.json`: this week's games with the NFL's official injury report (nflverse `injuries/injuries_<season>.csv`, CC BY 4.0), stadium roof and location, and the model's pick adjusted for injuries. Built daily by `python3 -I data/build_gameday.py <games.csv> <injuries.csv> 2026` after `build_projections.py` has run at least once. Each listed player counts by his chance of missing the game (Out 1, Doubtful 0.85, Questionable 0.3; practice-only listings 0.35 or 0.1) x his position's worth in Elo points x his snap share, capped at 150 per team. Weather is added in the page from the US National Weather Service hourly forecast (api.weather.gov, US public domain, fetched by the viewer's browser) for open-air US stadiums: wind over 12 mph, likely rain or snow and 25°F or colder take points off the projected total, and high wind narrows the spread. Tapping a game in the current week opens its preview, team stats and injury report.
- `data/depth.json`: each team's listed depth chart (offense, defense, special teams) from the newest snapshot of nflverse `depth_charts/depth_charts_<season>.csv` (CC BY 4.0). Built daily by `python3 -I data/build_depth.py <depth_charts_2026.csv> 2026`. Players carry their gsis id. It is listed order, not snap counts. Shown as "Listed depth chart" under the snap-ordered chart on each team page (`fillListed` in src.html).
- `data/injuries.json`: every player's official injury-report history this season (game status and practice level by week), keyed by gsis id, from nflverse `injuries/injuries_<season>.csv` (CC BY 4.0). Built daily by `python3 -I data/build_injuries.py <injuries_2026.csv> 2026`. Shown as the "Injury report" table at the bottom of the On the field tab on each player sheet (`fillInjury` in src.html).
- Pick'em (top of `/scores`, `pk*` functions in `src.html`): fans pick the winner of each game on the game cards and see their record next to the model's on the same games. No account and no server: picks live in the browser's localStorage under `pc.pickem` as `{ season, picks: { gameId: { t, m, at } } }`, where `m` is the model's pick (the injury- and weather-adjusted `gPick`) when the fan picked, so each pick is graded against the model the fan saw; picks without `m` fall back to the weekly pick in `projections.json`. Picks lock at kickoff (`gameday.json` kick time, else the schedule's Eastern date and time) and ties count for neither side. The home Scores tile shows the fan's record. A new season starts a fresh pick sheet.
- Sources not used: Pro Football Reference and Next Gen Stats data (owner's rule; one written exception: nflverse `snap_counts`, PFR's transcription of the snap counts in the NFL's official gamebooks, because no free in-season alternative exists), nflverse `contracts` (Over The Cap), FTN charting (CC BY-SA 4.0: derived data would have to be shared under the same license). nflverse `ff_opportunity` has no CSV or parquet release, so it is not built. Check a dataset's source and license before adding it.
